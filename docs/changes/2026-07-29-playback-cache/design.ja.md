# 再生機能とキャッシュ状態の設計

## UI

共通プレイヤーではシャッフルとリピートを隣接させます。両方を開閉記号非表示のボーダーレスメニューにし、シャッフルには「現在の再生範囲で切り替え」と「ライブラリ全体を今すぐランダム再生」の2操作を置きます。

キャッシュ画面のヘッダーは既存のコンパクトな補助行を使い、`曲数・整形済み容量`、その下にキャッシュパスを表示します。

右ペインでは上部プレイヤーを現在曲情報の唯一の表示元とし、詳細タブは曲名・アーティスト名を重複表示せず直下から開始します。

## 再生対象の選択

ライブラリ全体ランダム再生は独立した再生範囲として扱います。次曲へ進むたびに、登録済みのセキュリティスコープ付きルートを解決し、現在のファイルシステム上で接続を確認します。1つ以上接続中ならそのルートの利用可能曲を、すべて未接続なら `local_cache` と結合した曲を選び、キャッシュファイルの実在も確認します。

選択はインデックスを使えるIDしきい値と折り返しで行い、`ORDER BY RANDOM()` や全件配列化を避けます。選択ごとにシードを進めます。

## キャッシュ集計

`librarySidebarCounts()` で既存の件数とともに `SUM(local_cache.file_size)` を返します。`LibraryViewModel` がバイト数を公開し、`ContentView` で `ByteCountFormatter` により表示します。

## ウィンドウ復元

ルートウィンドウは、通常プレイヤー表示中の移動・サイズ変更後に `NSRect` を `UserDefaults` へ保存します。ミニプレイヤーへ切り替える直前にも通常フレームを保存し、ミニ表示中のサイズ変更通知は無視します。起動時は保存フレームを検証して適用し、既存の画面内補正を通すことで、外したディスプレイ上にウィンドウが残ることを防ぎます。

## 原因の要約

- リピート表示: SwiftUI `Menu` の標準開閉記号がSF Symbolsの横に追加されていた。
- 全体ランダム不足: シャッフルが現在の一覧候補だけを対象にしていた。
- 容量表示不足: DBには `file_size` があるのに、サイドバー集計が件数しか返していなかった。
