# 要件: チェック式自動処理と狭幅レイアウト

## メタデータ自動処理

- 自動処理のチェックをオンにしたら、バックグラウンド処理を自動で開始または再開する。
- チェックをオフにしたら処理をキャンセルし、次回起動時にも再開しない。
- 同じ自動処理に対する別の開始・停止ボタンは表示しない。
- 実行中、待機中、完了の状況は操作を伴わないステータス文字として残す。
- 安全条件、再開カーソル、MusicBrainzの再試行操作、保護DB方式のAPIキー保存は変更しない。

## ライブラリの狭幅表示

- 中央ペインを狭めても、キャッシュ設定、表示項目、検索窓を重ねたり欠けさせたりしない。
- 狭幅では検索窓を独立した全幅行へ移し、小さい操作群を上段に残す。
- 検索窓は実用的な最小幅を保ち、入力可能な状態を維持する。
- 曲一覧は横スクロールを許容するが、列見出しを右ペインへめり込ませない。

## プレイヤーの狭幅表示

- 右ペイン最小幅でも、ジャケット、曲名、ランダム、リピート、ミニ化、音量、前後・再生、再生位置をすべて表示する。
- 通常プレイヤーとミニプレイヤーは同じ操作を共有し、必要な幅で自動的にコンパクト配置へ切り替える。
- 十分な幅がある場合は現在の横並びを維持する。

## 外部記事の自動翻訳

- 管理画面の「表示」に、内部ブラウザの自動翻訳を保存するオン・オフを追加する。
- オフでは翻訳サービスを経由せず、元ページのURLをそのまま開いて移動する。
- オンでは従来どおり、外部記事をアプリの選択言語で表示する。
- 設定変更時は現在表示中の記事を元ページまたは翻訳ページとして直ちに再読込する。
- 右ペインの翻訳状態文字は表示全体をクリック可能にし、同じ保存設定を切り替える。

## 表記ゆれの統一

- 各候補ペアの上側・下側の両方に、その表記へ統一する操作を表示する。
- 統一前に、対象項目、変更元、変更先、対象曲数を確認できるようにする。
- 確定した変更はDBだけを書き換えず、既存の安全なタグ書込とオフライン保留経路を使う。
- 完了後は診断画面の文脈を必要以上に初期化せず、解消した候補と件数を更新する。

## 安全性と互換性

- APIキーをKeychainへ戻さず、Gemini/OpenAIともアプリ内保護DB方式を維持する。
- 検証時に実ライブラリのスキャンを起動しない。
- 関係のない既存変更を壊さない。
