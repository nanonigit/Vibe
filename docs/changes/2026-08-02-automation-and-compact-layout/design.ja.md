# 設計: チェック式自動処理と狭幅レイアウト

## 根拠

Lazywebで確認したTodoist、Sunsama、Linear、Microsoft Loopのデスクトップ設定画面では、継続的な自動設定はトグルを唯一のオン・オフ操作にし、状態や進捗は説明表示として扱っています。Amplitudeなどのテーブル画面では、横幅が不足すると検索を密度の高いテーブル操作群から分離しています。Vibeの見た目を変えすぎず、このパターンを採用します。

## 自動処理の状態モデル

保存される真偽値を唯一の状態元にします。

1. `false -> true`: `true`を保存し、未実行なら対応処理を開始する。
2. `true -> false`: `false`を保存し、対応タスクをキャンセルして一時的な実行状態を消す。
3. アプリ起動: 真偽値を読み、オンの処理だけを開始する。
4. 処理完了: 今後の取り込みや次回起動でも処理できるよう、チェックはオンのままにする。

進捗行は文字表示だけにします。MusicBrainzの明示的な再試行は、オン・オフ操作の重複ではなく完了済みの例外結果を再処理する操作なので残します。

## ライブラリヘッダーのレスポンシブ化

`ViewThatFits(in: .horizontal)`で2つの配置を切り替えます。

- 通常: 情報、操作群、固定幅検索窓を1行に並べる。
- 狭幅: 情報を上段、操作群を次段、検索窓を利用可能幅いっぱいの行へ配置する。

狭幅の検索窓は360ポイント固定をやめ、可変幅にします。

## プレイヤーのレスポンシブ化

共通プレイヤー内部に2つの配置を用意し、`ViewThatFits`で切り替えます。

- 通常（最低420ポイント）: ジャケットの右に、曲情報と補助操作を含む列を置く。
- 狭幅: 上部にジャケットと曲情報、その下に補助操作、続いて再生操作とシークを全幅で置く。

狭幅でも操作は削除しません。

## 翻訳状態と現在ページの再読込

保存される真偽値をBindingとして内部ブラウザへ渡します。ツールバーの状態表示はラベル全体を押せるプレーンボタンにし、アイコンと文字を同じクリック領域にします。WebKit側は翻訳URLを作る前の元記事URLを保持します。設定変更時は、オフなら元URL、オンならその翻訳URLを現在ページとして再読込します。オフの間はナビゲーション判定でも翻訳経路を完全に通しません。

## 表記ゆれ選択と安全な書込経路

候補行では確認用リンクを残し、上下の値それぞれに「この表記に統一」を追加します。選択すると候補と採用値を含む確認要求を作ります。確定後は、反対側の値と完全一致する曲だけを取得し、既存の一括メタデータ更新経路へ渡します。これによりファイル検証、ID3修復方針、オフライン保留、進捗、操作ログを維持します。変更元の件数が0になった候補は既存の更新処理で消えます。

## 原因概要

現在は保存設定のチェックボックスと開始・停止ボタンが並存しています。AIジャンルの停止ボタンはタスクだけを止め、保存済みチェックをオフにしないため、次回起動で再開します。またヘッダーの固定幅とプレイヤー先頭行の必要幅がペイン幅を超え、クリップされています。
