# 根本原因分析: 自動標準化後も日本語ジャンルが残る

## 症状と影響

管理画面では自動標準化がオンなのに、ジャンル一覧には日本語表記が残ります。利用者は、故障、未完了、意図的な保持のどれなのか判断できません。

## タイムライン

- 2026-08-01: 静的 `GenreNormalizer` とバックグラウンド統合処理を追加。
- 2026-08-02 17:23: 起動中のv0.16で日本語ジャンルを確認。
- 2026-08-02 17:28: 管理画面でトグルがオンであることを確認。別機能の未分類AI解析は実行中だった。
- 調査: 画像内の日本語ジャンルはすべて静的辞書に未登録で、安全ガードが元表記を返していた。

## 5 Whys

1. なぜ日本語ジャンルが残るのか。元表記が別名辞書にないため。
2. なぜ未知表記を翻訳しないのか。部分置換で誤った混在表記になる可能性があり、安全ガードが元表記を返すため。
3. なぜ辞書で全件を扱えないのか。AI生成・外部取り込みの表記は終わりのない語彙になるため。
4. なぜ停止したように見えるのか。完了時に進捗を消し、「自動整理はオンです」へ戻るため。
5. なぜ状況が分からないのか。未解決件数、保持される完了結果、出典付きナレッジがないため。

## 特性要因図

- データ: 増え続ける日本語別名と大小文字の揺れ。
- アルゴリズム: 静的な完全一致・部分一致のみで、未知値は安全に保持。
- 状態: カーソルは保存するが、完了・未解決サマリーは保存しない。
- UI: 有効と完了・待機中を同じ文言で表示。
- 検証: 既知別名と未知日本語の保持はテスト済みだが、オンライン解決経路がない。

## 是正・再発防止

- 元表記をキーにする小さなジャンルナレッジテーブルを追加する。
- 未知の日本語表記は、検証可能な出典付きWeb情報で解決する。
- 解決できない値は変更せず、未解決件数を明示する。
- 新しいAIジャンル名はすべて英語に固定する。
- 直近の完了件数を保持し、ジャンルUIに出典を表示する。
- 永続化、言語方針、状態表示の回帰テストを追加する。

## 検証結果

- 最初の回帰テストは、ナレッジモデルと永続化APIが未実装の状態で失敗した。
- 最終的に176テストすべてが成功し、失敗・スキップは0件だった。
- Debugとarm64 Releaseのビルドが成功し、別ファイルのv0.17成果物はアドホック署名のdeep/strict検証に合格した。
- 本番DB、音源ファイル、インストール済みアプリ、実行中の正規化カーソルは変更していない。
