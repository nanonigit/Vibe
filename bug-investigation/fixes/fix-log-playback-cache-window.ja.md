# 修正記録: プレイヤー操作・キャッシュ状態・ウィンドウ復元

## タイムライン

1. 回帰テストで不足動作を再現。
2. キャッシュ容量集計と有界ランダム選択を追加。
3. 接続ルートを都度確認し、実在キャッシュへ切り替える全体ランダムを追加。
4. 両メニューの開閉記号を隠し、シャッフルとリピートの隣接を維持。
5. 画面内補正付きの通常ウィンドウフレーム永続化を追加。
6. 158件のテスト成功を確認。

## 5 Whys

1. なぜリピート表示が崩れたか: 標準メニューの開閉記号が表示されたままだった。
2. なぜ残ったか: メニュースタイルだけを指定し、開閉記号を無効化していなかった。
3. なぜ全体ランダムがなかったか: 再生状態が既存の再生順内でのオン／オフしか表していなかった。
4. なぜ容量がなかったか: 集計がキャッシュ行数だけで、記録済みバイト合計を返していなかった。
5. なぜウィンドウが復元されなかったか: ミニプレイヤー復元はプロセス中の一時状態だけで、起動をまたぐ保存がなかった。

## 特性要因の要約

- UIフレームワーク: 標準開閉記号。
- 状態モデル: 全体シャッフル範囲の欠如。
- データクエリ: キャッシュ容量集計の欠如。
- ライフサイクル: ウィンドウフレームがSwiftUIの一時状態だけ。
- 規模: 全件配列化を避け、インデックス利用の有界選択が必要。
