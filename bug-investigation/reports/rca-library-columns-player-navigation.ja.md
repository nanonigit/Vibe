# 根本原因分析: ライブラリ列とプレイヤー遷移

## タイムライン

1. 初期一覧は曲名、アーティスト、アルバム、件数中心で構築された。
2. 後からメタデータ自動補完で年とジャンルが利用可能になった。
3. 一覧の契約とプレイヤー表示は更新されなかった。
4. 自動補完の進展により、表示不足が明確になった。

## 5 Whys

1. なぜ情報がないか: 対応列と操作がない。
2. なぜ列がないか: ソートと集計モデルに項目がない。
3. なぜモデルにないか: 初期の一覧契約がメタデータ自動補完より古い。
4. なぜプレイヤーから移動できないか: 共通プレイヤーの情報が受動的な文字だった。
5. なぜ残ったか: メタデータから遷移までを表す回帰テストがなかった。

## 特性要因

- **モデル:** 年ソートとアーティストジャンルがない。
- **データ:** 決定的な代表ジャンル集計がない。
- **表示:** 表示切替、幅、ヘッダー、セルがない。
- **操作:** プレイヤー情報が受動表示。
- **テスト:** 要求を通したソース契約がない。

## 根本原因

メタデータ生成機能の拡張に、読み取り側の表示・遷移契約が追随していなかった。
