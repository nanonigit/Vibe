# RCA: ライブラリ検索のフォーカス消失

## タイムライン

- T+0 ms: 文字入力により `searchText` が変化する。
- T+0 ms: 検索待ち状態が検索中テキストを追加し、固有幅が変化する。
- T+280 ms: デバウンス後の遷移が表示セクションを変更し、結果を読み込む。
- レイアウト中: `ViewThatFits` が別候補を選択し、検索サブツリーが再生成され得る。
- 結果: AppKitが古いテキスト欄のファーストレスポンダーを解除する。

## 5 Whys

1. なぜ入力が止まったか。テキスト欄がファーストレスポンダーを失ったため。
2. なぜ失ったか。SwiftUIのサブツリーが差し替わったため。
3. なぜ差し替わったか。`ViewThatFits` が候補を切り替えたため。
4. なぜ候補が切り替わったか。条件付き検索中表示とセクション操作が固有幅を変えたため。
5. なぜ検索欄に影響したか。検索欄自体が適応レイアウトの両候補内に重複し、安定した親所有のフォーカス状態もなかったため。

## 特性要因

- レイアウト: 可変幅と候補切替。
- 状態: 入力中に待機・読込・セクション変更が発生。
- ビュー同一性: 適応レイアウト分岐に検索欄が重複。
- フォーカス: 安定したSwiftUI状態ではなくAppKitだけが保持。
- テスト: 検索欄の同一性と寸法を守る回帰検証がなかった。

## 根本原因

状態に応じた固有サイズで選択される適応レイアウト分岐の内側に、フォーカス対象を置いていたこと。
