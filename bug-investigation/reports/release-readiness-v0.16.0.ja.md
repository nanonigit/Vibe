# リリース準備分析: Vibe 0.16.0

## 対象

蓄積したテスト済みVibe変更をApple Silicon向けGitHub Releaseとして公開し、ローカルデータを露出させず、バージョンやチェックサムの不一致を起こさずに公式Homebrew Caskを更新する。

## タイムライン

1. 未コミット差分、リモート`main`、現在の`v0.15.0`リリース、`homebrew-vibe` Caskを確認した。
2. リリース情報を変える前に要件と公開順序を定義した。
3. 日英ドキュメントとバージョン情報を更新した。
4. 全テスト、arm64 Releaseビルド、署名、アーカイブ、チェックサムの各ゲートを実行する。
5. 製品変更だけを正確にレビューしてプッシュする。
6. GitHub配布物を公開し、独立して再検証する。
7. 公開配布物のチェックサムでHomebrew Caskを更新、検証する。

## 5 Whys: 壊れたHomebrewリリースの防止

1. Homebrewインストールが失敗する理由は？ Caskのバージョンまたはチェックサムが配布物と一致しない可能性がある。
2. なぜ不一致になる？ 最終アーカイブの作成・アップロード前にCaskを編集する可能性がある。
3. なぜ起きる？ リリース、チェックサム、Tap更新を別々の作業として扱う可能性がある。
4. なぜ危険？ GitHub上の配布物が再梱包・置換されても、Caskは以前のダイジェストを参照し続けるため。
5. どう防ぐ？ 公開配布物をダウンロードし、ローカル検証済みアーカイブとのSHA-256一致を確認してからTapを更新する。

## フィッシュボーン分析

- **ソース:** 無関係な`.agents/`ツールをステージする可能性。パスを明示したステージで防止する。
- **ビルド:** 古いDerivedDataロックや古いアプリを梱包する可能性。新しいRelease生成先とBundleバージョン確認で防止する。
- **アーキテクチャ:** UniversalまたはIntelバイナリを誤配布する可能性。`file`と`lipo -archs`で防止する。
- **署名:** ネストしたFrameworkの署名不整合が梱包後に発覚する可能性。ZIP化前後のdeep strict検証で防止する。
- **ドキュメント:** READMEと実装がずれる可能性。機能説明をソース／テストへ対応させ、日英を相互更新する。
- **配布:** Homebrewチェックサムがずれる可能性。Caskコミット前にリモート配布物をハッシュする。

## リリースゲート

- 全テストが成功する。
- `git diff --check`が成功し、ステージ内容に認証情報パターンがない。
- アプリのバージョンが0.16／ビルド16、実行形式がarm64である。
- ZIP化前と展開後のdeep strict署名検証が成功する。
- 公開後にGitHub配布物の名前、サイズ、SHA-256を確認する。
- Homebrew Caskが同じバージョン、URL形式、SHA-256を参照する。
