# 根本原因分析: プレイヤー遷移

## タイムライン

1. 共通プレイヤーのソースへクリック処理を追加した。
2. インストール済みアプリのビルド日時より後に作業ツリーのソースを更新した。
3. 古いインストール済みアプリが動き続け、新しいクリック処理が画面へ反映されなかった。
4. ソース確認で、セクション／検索状態の引継ぎとアルバムアーティスト不一致も見つかった。

## 5 Whys

1. なぜクリックしても動かないように見えたか？ 実行中バイナリが要求した詳細を確実に表示しなかったため。
2. なぜ実行中バイナリに期待動作がなかったか？ `/Applications/Vibe.app` がソース変更より古かったため。
3. なぜ新しいソースでも一部の曲で失敗し得たか？ 現在のセクションと検索状態を引き継いでいたため。
4. なぜアルバムが空になる可能性があったか？ DBの分類キーであるアルバムアーティストではなく曲アーティストを使っていたため。
5. なぜ検出できなかったか？ 以前の契約テストはクリック呼出しの存在だけを確認し、遷移先状態や配布済みバイナリ日時を確認していなかったため。

## 特性要因

- 配布: インストール済みアプリがソースより古い。
- 遷移状態: セクションと検索を引き継ぐ。
- メタデータ: 曲アーティストとアルバムアーティストが異なる場合がある。
- テスト: 呼出し存在だけで遷移動作の確認が不足。
- 環境: Xcodeの通常テストランナーはパスコードロック済み端末の探索で停止するため、正常生成されたmacOSテストバンドルを `xctest` で直接検証した。

## 根本原因

今回見えていた直接原因は古いアプリの実行です。コード上の寄与原因は、暗黙的な遷移コンテキストと誤ったアルバム分類アーティストでした。
